## A — needed before the rewrite

| | Question | Where the pages stop | Recommended default |
|---|---|---|---|
| Q1 | **Sessions on an adopted tunnel.** After a crash with the descriptor store (P14), the new instance owns the tunnel but knows neither the sessions' device indexes nor their creation-time temporary names, so neither the S9 proof nor the S22 proof exists. How are they matched, which are kept, which deleted? | P14 says only "they are managed as after a loss of notifications" | A session of an adopted tunnel is matched to the configuration by `session_id`, `peer_session_id`, `cookie` and `peer_cookie`, all of which `SESSION_GET` reports (`l2tp` 0.4.0). A match whose device bears the configured name is adopted as published and unmanageable (S20). A match whose device bears any other name (a session caught mid-staging, or renamed by a manager) and every non-match is deleted by identifier **within the adopted tunnel** and created again as at start-up: the tunnel is owned through its socket, and a session on it is either the daemon's or an operator's hand-made one, which R17–R18 already forbid. The identifiers of the deleted sessions are free at once or after the K18 wait. |
| Q2 | **Which renames use `rsl2tp-r` names.** S11 says renames "go through temporary names so that no step collides". Every rename, or only the colliding ones? Observability (O9) and the number of kernel operations differ. | S11 | Only a rename whose target name is held by another owned session of the same reconcile (a swap or a cycle) goes through a temporary name; every other rename is one `RTM_SETLINK`. |
| Q3 | **Temporary-name retries.** S7 says a taken temporary name makes the daemon "pick another". How many times before the attempt counts as a transient failure? | S4, S7 | Eight draws; then the creation is a transient failure retried at the next reconcile (the chance of eight collisions among 16 million names is negligible, so a lasting failure here means a namespace full of foreign `rsl2tp-t` devices, which R19 forbids). |
| Q4 | **Event-monitor filter contents.** K10 and A5 say the monitor is "filtered to the events the reconciler needs" without listing them. | A5, K10, M16 | The classic BPF program passes `RTM_NEWLINK` and `RTM_DELLINK` whose `ifi_family` is `AF_UNSPEC` (E5), and `RTM_NEWADDR` and `RTM_DELADDR`; it drops every other message type and every link message of another family (`AF_BRIDGE`, `AF_INET6` protocol state). Matching by name or index stays in the loop, because cBPF cannot read attribute strings cheaply. |
| Q5 | **How external deletion is noticed for a session without a device proof** (adopted sessions, sessions after a loss). S27 relies on the observed removal of the device, which needs its index. | S27, S20 | Subscribe the L2TP generic-netlink socket to the `l2tp` multicast group: the kernel multicasts `L2TP_CMD_SESSION_DELETE` and `L2TP_CMD_TUNNEL_DELETE` for every deletion commanded over netlink (`l2tp_netlink.c:277-278`, `664-665`), which is exactly an operator's deletion; deletions caused by a socket close are not notified, and need not be, since that is the daemon's own. The event names the identifiers, so it serves every session, proved or not, and costs no index. Adds a K fact and an E rule; removes the "either order" reasoning of S27 for this path. |
| Q6 | **The library's side of the hand-over.** L1 forbids the library to read environment variables and L12 shows the pattern for a tunable write; nothing says how adopted descriptors enter the library or how it asks the program to push a socket to the store. | L5, L9, L12, P14 | `Service::new` and `Runtime::new` take an optional list of adopted descriptors (`OwnedFd` with the tunnel identifier the program read from `LISTEN_FDNAMES`); the runtime verifies them (P14) and emits two new `ControlEvent` variants, `StoreSocket { tunnel_id, fd }` when a tunnel exists and `ForgetSocket { tunnel_id }` before it closes one, which the program answers through the control handle as it does for the tunable (L12); until the answer to `ForgetSocket` arrives the close waits, bounded by the two seconds of T8. |
| Q7 | **Restart through the control handle.** E26 says "or the control handle", but the exec is a process concern the library may not perform (L1). | E26, L6, P26 | `Control::restart` is a request the service delivers to the program as a callback, like the reload callback; the service finishes the operation in progress, stops its timers, and calls the callback with the list of tunnel descriptors; the program execs. If the callback returns (the exec failed), the service resumes. |

## B — shapes the interface

| | Question | Where the pages stop | Recommended default |
|---|---|---|---|
| Q8 | **The command line.** The pages name `--check`, `--verbose`, `--adopt-version` and "the main file and drop-in directory given on the command line", and P26 says the binary "MAY offer" a restart form. No complete list, no PID-file flag, no `--version`, no foreground mode for `Type=simple` units and container entry points. | P3, P22, P26 | `rs-l2tpd [--config FILE] [--config-dir DIR] [--pid-file FILE] [--verbose] [--check | --foreground | --restart | --adopt-version | --version]`. `--foreground` skips the double fork and the PID file and reports readiness by returning from nothing (the process simply runs; `Type=simple` users get no readiness, which P6 allows as "readiness means nothing to the rest of the boot"). `--restart` sends `SIGUSR2` to the PID in the PID file and exits 0 if the signal was delivered. Unknown options exit 2. |
| Q9 | **Default PID-file path.** "The configured path" is never given a default. | P10, P22 | `/run/rs-l2tpd.pid`, changeable at build time like the configuration paths (`PID_FILE_PATH`) and by `--pid-file`. |
| Q10 | **Daemon user and privileges.** The pages say "the daemon user" and require three capabilities, and the README calls a unit that "runs as root with no capability set" a defect, but never say whether the daemon drops privileges or which user the unit names. Affects P10's ownership rules and P25's sysctl write. | P10, P21, R49 | The daemon never changes user itself (no `setuid` logic, nothing to get wrong). The unit runs it as root with `CapabilityBoundingSet=CAP_NET_ADMIN CAP_NET_RAW CAP_NET_BIND_SERVICE` plus the ambient set, `NoNewPrivileges=yes`; "the daemon user" is whoever starts it. A later `User=` with `AmbientCapabilities=` works unchanged (a net sysctl is writable by a process holding `CAP_NET_ADMIN` in the namespace's user namespace). |
| Q11 | **Log line format.** O1 fixes the sink and the level, not the shape. | O1 | `LEVEL target: message` on one line, no timestamp (the journal and every supervisor add one), target being the module; `--verbose` adds the debug level. No `RUST_LOG`: the library reads no environment (L1) and the binary's only knob is `--verbose`. |
| Q12 | **The installer.** A1 and L1 list "the installer" among the binary's duties; nothing says what it installs, how it is invoked, or that it exists. | A1, L1, P23 | Remove it from the pages. Installation is the package's job (`docs/installation.md`); the unit file ships in the repository. If a form is wanted later it is `--install-unit`, writing the unit to a given path and nothing else. |
| Q13 | **`--adopt-version` output.** P26 says the target "prints a hand-over protocol version". | P26 | Prints exactly `rs-l2tpd-adopt 1` and a newline on standard output and exits 0; the old instance execs only on an exact match of a version it speaks. |
| Q14 | **`FDNAME=` of stored sockets.** P14 says "named by the tunnel identifier". | P14 | `t` followed by the decimal tunnel identifier (`t17`); any other name in `LISTEN_FDNAMES` is closed unread. |
| Q15 | **Daemonisation details.** P4 fixes the double fork, the umask ("restrictive") and the working directory; not `setsid`, the standard descriptors or the umask value. | P2, P4 | `setsid` in the intermediate child; standard input reopened on `/dev/null`; standard output and error kept (the journal is behind them); umask `077`; the PID file created `0644` explicitly so that `systemctl` can read it; directories created `0755`. `SIGPIPE` ignored, so that a parent that died before readiness is an `EPIPE` the daemon ignores (README gap row G1/P11), not a death. |

## C — defaults a test must pin

| | Question | Where the pages stop | Recommended default |
|---|---|---|---|
| Q16 | **`--check` output order.** O8 says TOML with the files' keys. | O8 | Tables in the order `host`, `resolvers`, `tunnels`, `sessions`; entries in ascending byte order of their names; keys in the order of the C7, C8, C16, C17 tables; defaults that were not written are not printed. |
| Q17 | **Configuration names.** Keys of the three maps; nothing constrains them. | C5, O4 | Any non-empty TOML key without control characters; longer than 64 bytes is a hard mistake of the entry, so that log lines stay readable. |
| Q18 | **Exit code of the daemon after a failed shutdown step or a callback panic.** O7 says "non-zero". | O7 | `1` for a failed step, `2` for a panic. |
| Q19 | **Reload while the reload callback runs** (E19 "replaces it"): is the running callback cancelled, or does its result get discarded? | E19, P13 | It runs to completion and its result is discarded; the latest request runs next. Nothing is cancelled, because the callback may be blocking. |
| Q20 | **Which address the DUID reads when the interface has none yet** (V12 reads it "when the resolver starts"). | V12 | The read is retried with the resolver's thirty-second timer until the device exists and reports a six-byte address; until then the resolver has no DHCPv6 half and `ipv6` uses advertisements. |
| Q21 | **The scratch socket of E25.** "The scratch check at a reconcile" creates an `AF_INET6` L2TP socket; what if that fails (`EAFNOSUPPORT`)? | E25, P25 | Then there is nothing to check: the host has no `AF_INET6` sockets (T4) and the tunable is irrelevant; no report. |
| Q22 | **One timer or one wake-up per second.** M14–M15 fix intervals; whether the "one shared timer" for pending peers and the reconcile retry are the same tick is open. | M14, M15 | One tick of one second drives the reconcile retry, the pending-peer retry and the unbound-reconnect retry while any of them is armed; bound-device retries and left-out retries have their own. |
