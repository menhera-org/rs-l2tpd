## Findings, ranked

1. **D9 regressed (medium).** A single undecodable or foreign-family `RTM_NEWADDR`/`RTM_NEWLINK` record now poisons the dump permanently (`src/kernel/linux/rtnl.rs:96` `_ => return None` + `:228` `EPROTO`). Consequence on an affected host: perpetual `monitor_pending`, an unending "lost notifications" warning episode, and every address addition on a bind device ignored (`src/reconciler/events.rs:277-286`), i.e. bound tunnels no longer reconnect when their device gets an address. Fix: skip records of other families (return a "not ours" marker, not an error), and keep `EPROTO` only for a truncated/malformed inet record; add a dump-level test with a foreign-family record.
2. **A1 partly (low–medium).** Re-creation through the event path (`recreate_session` after `observed_removal`/`verify_session`) is always staged because the configured name is still in `reserved`; `release_departed` runs only inside `reconcile` (`src/reconciler/mod.rs:232`). This re-introduces the A1 MAC change for the S27 "deleted outside the daemon" case. Fix: call `release_departed()` (or drop the reservation directly, since absence was just confirmed) before `create_wanted_sessions()` in `recreate_session`; strengthen the test to assert the re-created session's `ifname()` is `l2tp0`.
3. **D4 note (low).** `remember_device` performs a `link_by_index(master)` netlink round trip on every converge of a tunnel whose bind device has a master (`events.rs:518-526` via `ladder.rs:56`), even when already cached. Guard with `vrfs.contains(&master)` / `masters` lookup first.
4. **D7 note (low).** `close_from` failure now aborts start-up (`fdstore.rs:140, 184-201`). Correct per P4, but a host that filters `close_range` and has a hard `RLIMIT_NOFILE` above ~10 M will fail to start where it previously (slowly) succeeded. Worth a line in the hosts page.
5. **E1 coverage gap (low).** `a_survivor_takes_a_removed_sessions_name_without_becoming_an_override` forces synchronous deletion; the asynchronous K18 case (survivor's rename hits the dying device, EEXIST, retried) is untested.
6. **Test looseness (low).** `completion_report_counts` injects six `dump` failures but `retain_devices` also consumes `dump` injections, so the exact timing of "resynchronised" is not what it appears to assert; it still proves the once-per-episode property. `payload_debug_is_redacted…` relies on `!contains("222")` for the full message, weak but redundant with the direct `format!` check.
7. **Upgrade note (info).** The B5 checks refuse a 0.1.5 PID file (mode 0666, per the audit), so `rs-l2tpd --restart` cannot be used to hand over from a running 0.1.5; the installer's new message already says `systemctl restart` is needed once. Documenting this in `docs/packaging.md` would avoid surprise.
