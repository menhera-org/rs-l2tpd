# Security / spec-conformance review: `src/bin/rs-l2tpd/` (process layer)

Tree: `main` @ 0cf9252. Specs read: process.md P1–P27, observability.md, configuration.md C1–C4/C10–C12, requirements.md R43/R49 row, library.md L13. Prior audit items (A1–C6) were taken as settled and are not repeated. Toolchain checked for the exec findings: rustc 1.99.1.

## Findings, ranked

### 1. Medium — Robustness / Spec (C3, P2, P9, P13): configuration files are read with no type or size bound
`src/bin/rs-l2tpd/files.rs:84` (`fs::read_to_string`) after `present()` (`files.rs:14`, `fs::metadata` only, no `is_file()`). A FIFO named `x.toml` in the drop-in directory, or given as `--config`, blocks in `open(2)` with no writer:
- at start-up this is before `daemon::start` (`main.rs:80` vs `:84`), so the parent never exits and, with the supplied unit's `TimeoutStartSec=infinity`, the service never becomes ready;
- on reload it hangs the `l2tp-reload` thread; `in_flight` never clears (`src/service.rs:352`, P13 "runs to completion"), so every later reload is silently lost until the process is restarted.
A multi-GB regular `.toml` is read whole into memory (OOM kill of the root daemon → every tunnel gone unless a store holds them). C3 classifies "cannot be read" as a per-file problem to report, not a stall. Fix: refuse non-regular files in `present()`/`read()` (report "not a regular file"), optionally cap the read.

### 2. Medium-Low — Security / Robustness (O1, P4): log output goes to whatever holds fd 2
`src/bin/rs-l2tpd/logger.rs:12-13` writes to fd 2 unconditionally; nothing ensures fds 0–2 are open at entry, and `fdstore::inherit` closes only from 3 up (`fdstore.rs:140`). Started by a supervisor or entry point with stderr (or stdout) closed, the first socket opened takes fd 2: the netlink socket, then after a restart or reconnect possibly a tunnel L2TP/IP socket. Each log line then becomes a `write(2)` on that socket — on a tunnel socket an L2TP data packet to the peer carrying log text (peer addresses, interface names, paths); on netlink a garbage request whose error reply the monitor must digest. `daemon.rs:30` `pipe2` can likewise land on fd 1/2. Fix: at the top of `run()`, open `/dev/null` on every fd in 0..=2 that `fcntl(fd, F_GETFD)` reports `EBADF`.

### 3. Low-Medium — Spec deviation (P26) / Robustness: a stat error on the handed-over PID file kills the re-exec'd image
`src/bin/rs-l2tpd/restart.rs:83` `pid.matches()?`: `matches()` (`pidfile.rs:230-236`) maps only `NotFound` to `false`; `EACCES`, `ELOOP`, `ENOTDIR` (a parent component replaced, an LSM denial, a mount change while the old image ran) propagate, `entry()` fails, `main` exits 1 (`main.rs:203-205`) and the inherited sockets are closed → every tunnel is deleted by the kernel (P26's "if the new program dies before adopting"). P26 says a non-matching identity means "leave the file alone and report it"; only an *invalid* marker/state is a startup error. Fix: treat `Err` like `Ok(false)` with a warning.

### 4. Low-Medium — Robustness / Spec (P14, P23, P5): an unusable `NOTIFY_SOCKET` aborts start-up
`src/bin/rs-l2tpd/main.rs:90-94`: `Store::new(...).transpose()?`. `UnixAddr::new` fails for a path > 107 bytes, `UnixDatagram::unbound()` fails when AF_UNIX is not allowed (an operator's own unit with `RestrictAddressFamilies=` lacking `AF_UNIX`, or any non-systemd supervisor that happens to export `NOTIFY_SOCKET`). The daemon then exits 1 before opening the kernel interfaces; under `Restart=on-failure` that is a 3-second crash loop. P14 says the store "is used only when the init system offers it"; P5 reserves hard failure for kernel interfaces (and retries those). Fix: log at error level and continue with `store = None`.

### 5. Low — Security: `--restart` trusts the PID file's location and content
`src/bin/rs-l2tpd/restart.rs:248-259`: `read_to_string(path)` (unbounded; a FIFO hangs), parse, filter `> 1`, `kill(pid, SIGUSR2)` as root. SIGUSR2's default action is termination, so:
- a stale file after a crash (P11 replaces it only at the *next start*) names a recycled PID → an unrelated process is killed;
- a `--pid-file` in a world-writable, non-sticky directory (P10 only *warns* at publication) lets any local user choose the target.
No ownership/mode/symlink check is made, unlike `publish()`. Fix: open with `O_NOFOLLOW`, require a regular file owned by the caller's euid with no group/other write bit, read at most ~32 bytes. (Verifying the target's identity would need `/proc`, which P23 forbids; the file checks are what remains.) Related doc drift: `docs/packaging.md:28,113` show `rs-l2tpd --restart` without `--pid-file` while the supplied unit uses `/run/rs-l2tpd/rs-l2tpd.pid` (`docs/packaging.md:52-55` and `docs/interface.md:128-130` have it right); with the default build that command reads `/run/rs-l2tpd.pid`, which after the legacy upgrade below is the *old* daemon's file.

### 6. Low — Spec / Robustness (P27 installer, P26): upgrading a legacy install leaves a daemon that re-execs the old binary
`src/bin/rs-l2tpd/setup.rs:46-61`: the legacy unit (`ExecStart=/usr/local/bin/rs-l2tpd`, `PIDFile=/run/rs-l2tpd.pid`, `contrib/rs-l2tpd.service.legacy:7-8`) is recognised and replaced, the new binary is written to `/usr/local/sbin/rs-l2tpd`, and `/usr/local/bin/rs-l2tpd` is left in place and unmentioned. The running legacy daemon's exec target is its own argv[0] path (`restart.rs:108-126`, by P26), i.e. `/usr/local/bin/rs-l2tpd`. The documented in-place upgrade (`rs-l2tpd --restart`, `docs/packaging.md:28`) therefore re-execs the stale old binary when it speaks adopt 1 (or is refused when it does not), and the installed version is never picked up until `systemctl restart`, which re-creates every tunnel — the opposite of what the page promises. Meanwhile the reloaded unit's `PIDFile=` no longer matches the running daemon's PID file. Fix: when the legacy unit is replaced, either also install the new binary atomically at the legacy path (then the in-place restart does pick it up) or print that an in-place restart will not take effect and `systemctl restart` is required. Also note the detection is byte-exact against one legacy text (`setup.rs:53`): any future template change turns every existing unedited install into "preserved operator-edited", so a second legacy constant is needed on the first template change.

### 7. Low — Robustness / Security: installer directory modes depend on the caller's umask
`src/bin/rs-l2tpd/setup.rs:15` (`create_dir_all` for `/usr/local/sbin`, `/etc/systemd/system`) and `:64` (`/etc/rs-l2tpd.toml.d`) create directories at `0777 & ~umask`. Root running `--setup-systemd` under umask 000 or 002 gets a group/world-writable drop-in directory that the root daemon reads at every reload → configuration injection by a local user. Files are chmod'ed explicitly (`:27`, `:72`); directories are not. Fix: `DirBuilder::new().recursive(true).mode(0o755)`, or `umask(022)` at installer entry.

### 8. Low — Robustness: `close_from` fallback can loop ~2^31 times
`src/bin/rs-l2tpd/fdstore.rs:173-186`: when `close_range` fails (seccomp profiles that return `EPERM` for syscalls they do not know — older Docker/libseccomp, relevant to the LXD/Incus requirement on older hosts) the loop runs to `rlim_max.min(i32::MAX)`; with hard `RLIMIT_NOFILE = infinity` that is minutes of `close()` before daemonisation. Use `rlim_cur` (fds are always allocated below the soft limit) with a sane cap.

### 9. Low — Robustness (P1/P2): an unreadable or deleted cwd fails start-up although argv[0] is absolute
`src/bin/rs-l2tpd/main.rs:24` and `:78` (`original?`): `getcwd` failing (`ENOENT` for a removed directory, `EACCES`) exits 1 even though `executable_at` (`restart.rs:110-112`) needs the cwd only for a relative argv[0]. P2 lists only command-line parsing as a possible pre-logging failure. Fix: move the `?` into the relative branch.

### 10. Cross-slice, in the P14 verification path (library, `src/reconciler/store.rs`) — Low-Medium Spec (P14, O3): `ESOCKTNOSUPPORT` is treated as uncertain, forever
l2tp 0.5 `TunnelSocket::from_fd` returns `ESOCKTNOSUPPORT` for a non-`SOCK_DGRAM` socket (`l2tp-0.5.0/src/socket.rs:457-461`); `kernel/linux/socket.rs:23-26` passes the raw errno through; `verify_inherited` (`src/reconciler/store.rs:221-231`) lists only `EINVAL|ENOTSOCK|EAFNOSUPPORT|EPROTONOSUPPORT|ENODEV` as definitive. A handed-over `AF_INET`/`AF_INET6` `SOCK_STREAM` or `SOCK_RAW` descriptor is therefore retried every second at debug level (`store.rs:238`), never retired or withdrawn from the store, and `incomplete` stays true (`reconciler/mod.rs:156`), so "reload completed" (`service.rs:303`) is never logged again. Add `ESOCKTNOSUPPORT` to the definitive list. (Checked the other `from_fd` paths: a vanished scope interface gives `ENODEV` from `SIOCGIFNAME`, UDP gives `EPROTONOSUPPORT`, non-OS l2tp errors map to `EINVAL` — all definitive.)

## Checked and found clean

- **pidfile.rs**: all operations relative to the directory fd (`openat`/`fstatat`/`renameat`/`unlinkat`); temp name random with `O_EXCL|O_NOFOLLOW`; in-place path re-verifies dev/ino, type, owner, nlink and mode on the *opened* fd; removal is inode-gated and never fails shutdown on inspection errors; rename over a symlink replaces the link, not its target; `fchmod` only on directories it created. Residual accepted by P10: directory symlinks are followed inside a root-owned, non-sticky, world-writable component (warned; `fs.protected_symlinks` covers sticky ones).
- **fdstore.rs inherit**: `LISTEN_PID == getpid()` gate; `LISTEN_FDS` bounded; names validated (no `:`/control chars, so no `FDNAME=`/newline injection) and re-validated at every send; `FD_CLOEXEC` set on every announced fd; env removed before any thread; `close_from` runs before anything is opened (P4). `BARRIER=1` pipe is `O_CLOEXEC|O_NONBLOCK` and bounded.
- **restart.rs exec**: probe output capped at `VERSION.len()+1` bytes and 3 s with kill/wait; exact-match; `unshare(CLONE_FILES)` keeps the shared table untouched on failure (so close-on-exec is never cleared in the live table); dup2 targets only 3..3+n; Rust 1.99 `Command::exec` restores `environ` on failure (std `sys/process/unix/unix.rs:394-410`) and inherits the signal mask (`:357`); `SIGPIPE` re-ignored by `pre_exec`; argv, `--foreground`, resolved path preserved; marker `1:<pid>` plus `LISTEN_PID` check; state hex-decoded, absolute, NUL-free. Residual: path TOCTOU between probe and exec (an `O_PATH` fd + `execveat(AT_EMPTY_PATH)` would close it; small window, atomic installs).
- **daemon.rs**: readiness pipe `O_CLOEXEC`; `EPIPE` logged on both writes; parent forwards SIGTERM/SIGINT to the grandchild, which has them blocked since `prepare()` ran before the fork, so a shutdown during start-up is collected by `sigwait` and `Signals::stopping()` is honoured in the kernel-retry loop (`main.rs:103`) and before readiness (`:142`); umask 077; stdin on `/dev/null`.
- **signals.rs**: the four signals are blocked before any thread exists; collector never blocks on the queue; shutdown clears pending reload/restart and wins; SIGUSR2 before readiness and during shutdown is ignored with a report; teardown via thread-directed SIGTERM after `stopped`; `prepare()` cannot alter glibc/musl internal RT signals (both libcs refuse).
- **P23**: the only `/proc` access in the binary is `tunable.rs:8`; capabilities via `capget`; no `/sys`.
- **args.rs / check.rs / logger.rs**: non-UTF-8 and unknown options exit 2 with usage; modes exclusive; `--check` has no side effects; log lines escape `\n`/`\r`; closed stderr is ignored, not a panic.
- **Panics**: no input-reachable panic found in the binary; remaining `unwrap`s are on established invariants (`parent()` after `file_name()`, `stdout.take()` after piped spawn, `fields[..]` after length check). `argv[0]` indexing is unreachable only for argc == 0, which Linux ≥ 5.18 prevents.

Skipped: live tests were not run; the library-side store/retirement logic beyond item 10, and the unit's sandbox under a real root systemd (C6 gap), were not re-verified.
